# Quality check, 2026-11-01 rules (applied 2026-11-17)

The owner's 10 rules, applied while M1 was built, on Windows 11 with Go 1.26.11. The race detector
needs cgo, which this machine lacks; CI runs `make test` with `-race` (not run yet).

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | pass | Every disk call goes through `store.call`: a per-attempt `context.WithTimeout`, at most `Retries` (0..5) retries with doubling backoff capped at 1 s, no retry on `disk.ErrInvalid`, `disk.ErrNotFound` or `ErrBadShard` (`TestRetriesAreBoundedAndTimeoutsApply`, `TestPermanentErrorsAreNotRetried`). The HTTP client has `http.Client.Timeout` and response-size limits; the server has read-header, read, write and idle timeouts and a 5 s shutdown limit. Failed fan-outs return every disk error joined (`errors.Join`). Ignored results are only response-body close and writes to a client that has gone, each commented (`internal/node/node.go`, `cmd/.../main.go`). |
| 2 | Writes safe to retry | pass | Shard files are written to a synced temporary file and renamed (`disk.Dir.Write`); rewriting the same version is a no-op (`TestWriteReadListDelete`). Deletes of missing files succeed; `Store.Delete` twice returns 6 then 0 (`TestDeleteIsIdempotent`). A put creates a new version and only removes older ones after all n shards are written; a failed put deletes its own version on all n disks (`TestFailedPutRollsBackAndKeepsOldVersion`). `Repair` run twice rewrites nothing the second time. The CLI writes `get` output by temp file and rename. |
| 3 | No race conditions | fixed | Memory disk under a mutex; Put/Delete/Repair of a key serialised by a per-key lock with reference counts (no leak, checked in the test); fan-out results go to per-index slots. Found while testing: a read could pick a version that a concurrent overwrite then deleted. Fix: the read starts over (at most 5 attempts with backoff). `TestConcurrentPutsAndGets` (4 writers, 4 readers) and `TestConcurrentWritersOnOneDisk`. `-race` in CI only. |
| 4 | Don't trust the clock | pass | Versions are ordered by a sequence number read from the disks plus a random id, never by time. Durations use `context.WithTimeout`, `time.NewTimer` and `time.Since` (monotonic). No timestamps are stored. |
| 5 | Read before changing | pass | No environment variables or config files are read; every CLI flag is in `usage` and the README. Only standard-library APIs available in Go 1.24+ are used (`go.mod` says 1.24 because the benchmarks use `testing.B.Loop`). Paths in the README exist (checked by `audit_repo.py`). |
| 6 | Never break compatibility | pass | First release. The shard header is JSON and unknown fields are ignored, so later versions can add fields (`TestShardFileFormat` "unknown field"); the magic `ECS1` marks the layout. Known constraint: the header must keep k and m equal to the store's settings, so changing k or m for existing objects needs a migration (RFC risks). |
| 7 | One source of truth | pass | Each disk holds the only copy of its shard; there is no cache or metadata service. Every shard header repeats the object metadata, and a read keeps only the largest group of agreeing headers. Placement is recomputed from the key and the disk list. Go version: CI and README say 1.26.11; `go.mod` gives the minimum language version (1.24). |
| 8 | Small changes, no secrets, validate input | pass | Standard library only, no secrets. Validation: keys 1..1024 bytes of UTF-8 without NUL, objects up to 64 MiB, k 1..64, m 1..32, k+m <= disks, timeout > 0, retries 0..5; disk and domain ids `[A-Za-z0-9][A-Za-z0-9._-]{0,63}`, at most 256 disks; object names 64 hex, version names `v<20 digits>-<16 hex>` (keys never become paths); shard files capped at 64 MiB + 64 KiB on write, read and HTTP body; header length capped at 32 KiB and every header field checked; node URLs must be `http(s)://host:port`; bench flags bounded; 23 bad CLI argument sets rejected. |
| 9 | Tests that can actually fail | pass | No skips or tautologies (`grep -rn "t.Skip" .` finds none). Empty, invalid and failure paths are covered for each entry point (see `docs/results/m1.md`). Mutation check below: 16 of 16 killed. Two real defects were caught by the tests while building (empty version name accepted; read racing an overwrite). |
| 10 | Re-verify | pass | `bash .tmp/check.sh` twice: gofmt clean, `go vet` clean, 65 tests passed, bench verdict printed, govulncheck "No vulnerabilities found.", `CHECK PASS`. `python .tools/audit_repo.py erasure-coded-object-store`: OK. CI not run yet (not pushed). |

## Mutation check

on the affected package), each file restored right after its run. Two first attempts (checksum and
rollback) did not compile because a variable became unused; they were rewritten so they compile
and then re-run, and only the compiling runs are counted.
